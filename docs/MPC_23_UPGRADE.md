# Phase 2.3 MPC upgrade

This upgrade starts from the phase-2 robustness harness and keeps the phase-1
model and results frozen. It is implemented in
`models/HT_ctrl_MPC_23.slx`, generated by `scripts/build_mpc_23_model.m` in
MATLAB R2023a. The base 14 controller parameters are loaded from the frozen
phase-1 parameter file; six new parameters configure the upgrade.

## Controller changes

1. **Output-disturbance estimate:** At each 0.05 s MPC update, the difference
   between filtered plant output and the preceding one-step prediction updates
   a bounded additive output-bias estimate. The estimate is held constant
   across the 40-step prediction horizon, complementing the existing bounded
   integral target trim.
2. **Adaptive measurement filter:** Only the signal entering MPC is filtered.
   The coefficient is 0.8 for four seconds after a reference change, or while
   the tracking error exceeds 0.03 pu. It is 0.05 during steady operation.
   Physical plant output and benchmark metrics are not filtered.
3. **Soft output constraints:** Predicted output outside 0.35–1.00 pu incurs
   a squared-violation cost with weight 20. This is equivalent to eliminating
   nonnegative slack variables from a quadratic soft-constraint objective.
   Existing hard actuator and input-move limits remain in the projection step.
4. **Anti-windup:** The phase-1 integral target trim is unwound by 10% per
   update when a hard actuator bound or soft output bound prevents correction
   in the direction of the tracking error. Integration otherwise uses the
   phase-1 ten-update gate and ±0.03 pu trim bound.

The optimizer still uses 20 warm-started projected-gradient iterations and
does not require Model Predictive Control Toolbox. Output-bound violations
remain possible because those bounds are deliberately soft; the actuator
limits are hard.

## Reproduce in MATLAB R2023a

From the repository root:

```matlab
addpath('scripts')
build_mpc_23_model
run_mpc_robustness_tests("noise", "mpc23")
run_mpc_robustness_tests("screening", "mpc23")
run_mpc_robustness_tests("stress", "mpc23")
```

The `noise` mode contains baseline, 0.003 pu, and 0.005 pu measurement-noise
cases. The `screening` mode uses the same 23-case matrix and metrics as phase 2.
The separate `stress` case commands 1.2 pu from 20 to 35 s, beyond the
1.0 pu soft output bound, before returning to 0.6 pu. It checks recovery and
hard actuator constraints; tracking the unreachable request is not expected.
Phase-2 results retain the `mpc_robustness_` prefix; upgraded results use
`mpc_23_`, so running both variants does not overwrite the comparison.

## Acceptance and scope

Use the original phase-2 thresholds: no hard input or move violations,
steady error below 0.001 pu, 35 s overshoot below 5%, and final steady
fluctuation below 0.008 pu. Compare each upgraded row with the identical
phase-2 case ID. This is a deterministic simulation study, not evidence of
stability or safety in untested operating conditions.

## R2023a validation result

The upgraded model completed all 23 deterministic screening cases. All 23
passed the original acceptance criteria, compared with 21 of 23 for the
phase-2 controller. Every case reported zero hard input and move violations.

| Case | Phase-2 steady fluctuation | Phase-2.3 steady fluctuation | Phase-2.3 IAE | Result |
|---|---:|---:|---:|---|
| Baseline | 0.004972 | 0.005446 | 0.606517 | Pass |
| Noise 0.003 pu | 0.008711 | 0.004315 | 0.605503 | Pass |
| Noise 0.005 pu | 0.011632 | 0.005578 | 0.632674 | Pass |

The two previously failing noise cases have 50.46% and 52.05% lower steady
fluctuation. At 0.005 pu noise, control total variation fell 64.52%. The
nominal IAE rose 2.31% from `0.592841` to `0.606517`, while nominal 35 s
overshoot changed from `1.6975%` to `1.7349%`. This is the principal measured
tracking cost of the noise mitigation. The 0.005 pu case has steady error
`0.000952 pu`, close to the `0.001 pu` acceptance limit, so the margin needs
further study with other noise seeds.

The separate stress-recovery run completed and passed its final-target and
hard-constraint checks. After the 1.2 pu request ended at 35 s, the response
settled to the 0.6 pu final target in `5.2145 s` with final mean error
`0.000317 pu`. Maximum absolute control was `1.1058`, below the hard `1.15`
limit, and both input and move violation counts were zero. Its large IAE
`5.37447` reflects the deliberately unreachable 1.2 pu request and should
not be compared with normal-screening IAE.
